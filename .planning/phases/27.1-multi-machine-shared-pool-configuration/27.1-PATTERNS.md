## Pattern Assignments

### `crates/tome/src/profiles.rs` (new config/model, transform)

**Analogs:** `crates/tome/src/config/mod.rs`, lines 42-64 and 152-235; `crates/tome/src/machine.rs`, lines 96-122 and 236-258.

Copy the load/parse/context structure, but do **not** preserve missing-file-as-default semantics for local settings or selected profiles. The new top-level loader must reject missing/empty/invalid/nonexistent selection before paths, discovery, or sync work.

```rust
let content = std::fs::read_to_string(path)
    .with_context(|| format!("failed to read {}", path.display()))?;
let prefs: MachinePrefs =
    toml::from_str(&content).with_context(|| format!("failed to parse {}", path.display()))?;
prefs.validate()?;
```

Use separate `#[serde(deny_unknown_fields)]` persisted structs and deterministic `BTreeMap`/`BTreeSet`, then project to the existing flat `Config`, as `Config` currently does (source: `config/types.rs`, lines 414-443). Reuse `DirectoryName` validation for profile names (lines 14-92), rather than accepting a raw filename segment.

### `crates/tome/src/migration_profiles.rs` (new service, file-I/O/batch)

**Analog:** `crates/tome/src/migration_v010.rs`, lines 148-189, 303-421; CLI integration fixture `crates/tome/tests/cli_migrate_library.rs`, lines 5-140.

Use a pure plan → render-to-writer → confirmed execute sequence. The migration plan owns all computed field mapping, backup destinations, and new bytes; rendering must occur before confirmation.

```rust
pub(crate) struct MigrationPlan { pub entries: Vec<MigrationEntry>, ... }
pub(crate) fn plan(...) -> Result<MigrationPlan> { ... }
pub(crate) fn render_plan_to(plan: &MigrationPlan, w: &mut impl std::io::Write) -> std::io::Result<()> { ... }
pub(crate) fn execute(plan: &MigrationPlan, dry_run: bool) -> Result<MigrationResult> { ... }
```

For the new multi-file contract: create timestamped sibling backups first; atomically write pool policy, profile, and settings; reload through the new effective-context loader; remove legacy `machine.toml` last. Existing atomic helpers protect individual targets only. Preserve `directory_overrides` only in legacy input/backup and bake its effective paths into the profile.

### `crates/tome/src/repo_sync.rs` (new service/utility, request-response)

**Analogs:** subprocess hygiene from `crates/tome/src/git.rs`, lines 15-59; Git command/result shape from `crates/tome/src/backup.rs`, lines 13-40 and 238-274.

Copy environment sanitization for **every** repository Git command:

```rust
let mut cmd = std::process::Command::new("git");
cmd.args(args)
    .current_dir(repo_dir)
    .env_remove("GIT_DIR")
    .env_remove("GIT_WORK_TREE")
    .env_remove("GIT_INDEX_FILE");
cmd.output().with_context(|| format!("failed to run git {}", args.join(" ")))
```

Implement a distinct pool Git layer; do not call `backup::snapshot` or `lib.rs::offer_git_commit`, because `backup.rs:119` and `lib.rs:2979-2982` use prohibited `git add -A`. Preflight from one read-only `git --no-optional-locks status --porcelain=v2 --branch --show-stash` snapshot; reject pre-existing staged/unmerged, behind/diverged, merge, and rebase states before mutation. Pull only after consent using fetch plus `merge --ff-only`; publish only deduplicated, repository-relative Tome-owned pathspecs with `git add -- <paths...>`.

### `crates/tome/src/pool.rs` (new service/model, CRUD/transform)

**Analogs:** candidate scan from `crates/tome/src/discover.rs`, lines 249-379; deterministic content identity from `crates/tome/src/manifest.rs`, lines 415-461; catalog model from `crates/tome/src/lockfile.rs`, lines 21-77 and 134-179.

Do not reuse the final selection branch in `discover_all`: it silently keeps the first same-name skill:

```rust
if let Some(&existing_idx) = seen.get(&name_str) {
    let existing = &skills[existing_idx];
    conflicts.push((name_str, existing.source_name.clone(), skill.source_name.clone()));
} else {
    seen.insert(name_str, skills.len());
    skills.push(skill);
}
```

Instead collect every candidate, hash each candidate with `manifest::hash_directory`, sort stable identities/candidates, then produce a pure reconciliation plan. A differing independent source returns a structured conflict before any library/manifest/catalog/exclude/distribution mutation. Equal content merges observation metadata. Only a conflict-free plan may invoke existing consolidate/distribute functions.

### `crates/tome/src/lockfile.rs` (model/service, file-I/O/CRUD)

**Analog:** `crates/tome/src/lockfile.rs`, lines 21-77 and 283-315.

Evolve `Lockfile` from regenerated current snapshot to authoritative catalog. Retain `BTreeMap<SkillName, _>` ordering and serde derives, add a schema version plus stable identity, initial observation, latest observation, and deterministic/deduplicated observation history. Do not retain the existing `generate()` replacement behavior (lines 143-179): it recreates entries from the manifest and loses prior facts.

Retain atomic persistence mechanics, including best-effort temp cleanup and contextual rename errors:

```rust
let tmp_path = tome_home.join("tome.lock.tmp");
std::fs::write(&tmp_path, &content)
    .with_context(|| format!("failed to write temp lockfile {}", tmp_path.display()))?;
if let Err(e) = std::fs::rename(&tmp_path, &path) {
    let _ = std::fs::remove_file(&tmp_path);
    return Err(e).with_context(|| format!("failed to rename lockfile {}", path.display()));
}
```

### `crates/tome/src/cleanup.rs` and `crates/tome/src/remove.rs` (services, file-I/O/plan-render-execute)

Replace source-absence deletion in `cleanup_library`: current Case 2 explicitly deletes a library entry when its configured source no longer yields it (lines 421-489). Shared-pool sync must preserve all accumulated content regardless of profile/source absence.

For explicit pool removal/restore, copy the plan-first command shape:

Pool removal must add the shared exclusion before (or atomically with) deleting pool/catalog state; restore clears it. Keep partial-failure reporting before persistence, as `cmd_remove_skill` does at `lib.rs:1136-1174`.

### `crates/tome/src/config/mod.rs`, `config/types.rs`, and `machine.rs` (config/model, file-I/O/transform)

Keep `directory_overrides` readable as a legacy compatibility path, but issue a deprecation warning at effective-load time and never write it in profile/settings creation flows. Preserve the current parse/expand/validate ordering for legacy input (`config/mod.rs:152-235`).

## Shared Patterns

### Error rendering and context
**Sources:** `crates/tome/src/config/mod.rs:46-64`, `crates/tome/src/git.rs:42-59`, `crates/tome/src/errors.rs:107-123`.

Use `anyhow::Context` at every filesystem/subprocess boundary, `bail!`/`ensure!` for policy violations, and `DomainTagged` sentinels for desktop-visible validation/conflict/Git categories. Preserve `{e:#}` error chains.

### Determinism
**Sources:** `crates/tome/src/config/types.rs:417-443`, `crates/tome/src/lockfile.rs:21-28`, `crates/tome/src/manifest.rs:415-461`.

Use `BTreeMap`/`BTreeSet` for persisted maps/sets; sort candidate and owned-path lists before render/stage; use `hash_directory()` rather than custom hashes. This is required for byte-identical repeated syncs and Git-reviewable catalogs.

### Atomic persistence vs. multi-file migration
**Sources:** `crates/tome/src/config/mod.rs:334-361`, `crates/tome/src/machine.rs:370-389`, `crates/tome/src/manifest.rs:386-412`.

All individual config/catalog writes are temp sibling + rename and temp cleanup on rename failure. Multi-file migration is ordered staging with validation before deleting the legacy machine file; it is not a filesystem transaction.

### Interactive mutation barrier
**Sources:** `crates/tome/src/lib.rs:965-993`, `crates/tome/src/lib.rs:1347-1388`.

Compute and render plans before confirmation. Honor dry-run as a no-write barrier. For `migrate profiles`, no noninteractive bypass exists; for Git `ask`, non-TTY is local-only with a warning.

### Git safety
**Sources:** `crates/tome/src/git.rs:28-40`; negative examples `crates/tome/src/backup.rs:119` and `crates/tome/src/lib.rs:2977-2982`.

Clear `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_INDEX_FILE`; gather status with `--no-optional-locks`; block rather than repair staged/unmerged/in-progress repositories; stage only explicit owned pathspecs. Never use `add -A`, reset, restore, checkout, or an automatic non-FF merge in pool sync.
