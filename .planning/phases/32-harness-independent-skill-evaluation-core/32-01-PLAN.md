# Phase 32 Plan 01: Deterministic provider-neutral evaluation core

## Objective

Deliver a library-only evaluation core for #604. TOML suites define provider-neutral cases; JSON results retain per-run evidence. A deterministic fake adapter supplies observations in fresh temporary workspaces. No command-line interface, subprocess, network call, model call, or mutation of Tome-managed state is introduced.

## Slice A — Contract and serialization

1. Add `pub mod evaluation` and `evaluation/{mod,contract,suite,result}.rs`.
2. Reuse `crate::ContentHash`; add no dependencies.
3. Implement `EvaluationSuite`, `ArtifactIdentity`, `EvaluationCase`, `ExecutionPolicy`, `Variant`, observation capabilities, terminal/grader states, run observations, grader results, and result aggregates.
4. Parse strict `suite.toml` at `evals/<suite-id>/suite.toml`, including schema-version, duplicate-ID, repetition, hash, and fixture-relative-path validation. Persist result documents as forward-compatible JSON.
5. **TDD:** first add tests for minimal suite round-trip; invalid version/hash/duplicate IDs/unsafe fixture paths; and JSON preservation of completed/timed-out/permission-denied/runner-error states. Run each test red before implementation.

## Slice B — Deterministic grading and comparison

1. Add `grader.rs` and `aggregate.rs` for final-text regex, artifact path/content, event occurrence/order, allowlist, and activation assertions.
2. Preserve missing required observation capability as `NotComparable` with a reason.
3. Implement weighted variant score and treatment/control comparison.
4. Positive activation is diagnostic-only. `NotActivated` is scoreable in both variants.
5. Delta requires matched fixture identity, repetition count, model pins, limits, isolation, and score-bearing grader set. Otherwise return no delta plus a reason.
6. **TDD:** hand-built observations prove each deterministic grader, equal outcomes (`delta = 0`), diagnostic positive activation, scoreable negative routing, and withheld delta for differing pins or terminal states.

## Slice C — Isolation and fake runner

1. Add `materialize.rs`, `runner.rs`, and `fake.rs`.
2. Hash-verify a source artifact before copying it into a fresh `tempfile::TempDir` for each run. Copy fixtures identically into treatment/control; only treatment gets the artifact. Sources and Tome library/manifest/lockfile/targets remain untouched.
3. Define `RunnerAdapter` plus `DeterministicFakeAdapter`, keyed by case, variant, and repetition. It returns prescribed observations only and never launches a process.
4. **TDD:** hash mismatch prevents runner invocation; workspace mutations do not alter sources; distinct repetitions receive distinct workspaces; missing adapter capability is non-comparable; full fixture-driven fake runs produce stable JSON and prove diagnostic activation/no-delta partial behavior.
